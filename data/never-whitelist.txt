# Never-whitelist - the protected set.
#
# These domains can never be released: the build refuses any whitelist rule (private listing
# or upstream exception) that would name them, and refuses any whole-tree rule that contains
# them. This is the answer to "I trusted a whitelist and it silently re-enabled tracking".
#
# Only core, unambiguous infrastructure belongs here. Everything else stays releasable so a
# legitimate false-positive report can still be fixed - a never-whitelist that swallows
# everything is the same failure mode as no never-whitelist at all.
#

# Entered as HOSTS, not registrable domains. That is the whole point of the priority rule: a
# broad `@baidu.com` release keeps Baidu working, while `hm.baidu.com` - the endpoint the feeds
# actually list, and the one that carries the page-visit beacon - is put back as a block rule.
# Protecting the registrable domain instead would refuse the `@baidu.com` release outright and
# break the service to keep one tracker blocked, which is the worse trade.
